idiolect — “what is it doing?” at the caret

Today the overlay has two states: mic-visible (recording) and gone. The moment you stop speaking the overlay is killed and the decode runs silently — on the current box that is ~8 s of dead air before text lands. These mockups add the missing third state: working. Same 74 px puck, same position (right of the caret), so nothing new appears on screen and nothing steals focus — the ring around the mic is the whole change.
Shipped: option B (indeterminate spinner + elapsed seconds), with the recording state given its own label and the live red from these mockups. Options A and C are NOT built — A needs a decode-progress hook whisper does not expose, and C is the natural follow-on. The measured numbers at the bottom are from CPU decoding; on a CUDA build the transcribing phase is a few hundred milliseconds, so it mostly matters for CPU takes and cold model loads.

Why every take felt slow, not just the first. Whisper encodes a padded 30 s window regardless of utterance length, so on CPU a half-second “yes” cost the same ~3.2 s as a ten-second sentence. The extra first-use delay was the 1.5 GB model paging in from disk.

GPU remains the big one: the same model on CUDA decodes 10 s of speech in 290 ms vs 8 370 ms on the old CPU config — but a CUDA build can silently fall back to CPU when the GPU is busy, which is exactly why the CPU path had to be fast too, and why the CPU-mode warning below matters.
Note the 0.5 s column. On CPU a one-word “yes” costs the same 3.2 s as a ten-second sentence — Whisper always encodes a padded 30 s window.
